## I. Project Positioning

**This is not an academic review, nor a policy proposal.**

This project is a hardcore database of engineering bottlenecks targeting production-grade engineering and fundamental science frontiers. Based on the baseline of systems cybernetics and thermodynamic laws, this repository systematically maps the core developmental bottlenecks in physics, engineering, life sciences, and social engineering. It contains **530** research coordinates with quantifiable metrics, physical boundaries, and engineering closure conditions, covering 17 critical technical domains.

The core deliverable of this repository is **an actionable, verifiable, and production-ready engineering coordinate**. Each entry can be independently decomposed into a complete R&D closure plan (90-point production-grade standard), rejecting vague academic visions.

## II. Core Evaluation Criterion (Validation Ironclad Rule)

All deductions and establishments of entries in this repository strictly follow the ten-character ironclad rule:

> **Logic must be closed-loop, physics must be reproducible.**

This repository does not accept any vague discourse that cannot be falsified. Deviation from these two rules is considered invalid deduction or pseudoscience. Each entry must contain: quantifiable metrics (physical thresholds or engineering parameters), traceable physical/mathematical mechanisms, explicit failure boundary conditions, and comparative analysis of multiple technical routes.

## III. Three Execution Rules for Engineering Implementation

All production-grade entries (No. 1–490) in this repository strictly follow these execution rules:

### 1. Materials and Component Criterion
**Mandatory use of COTS (Commercial Off-The-Shelf) industrial standard parts.** Specifying a single vendor or commercial model is strictly prohibited; only public industrial standards, performance specifications, and parameter thresholds are defined. If a special process is required, it must be proven unavailable through public market procurement, and its physical constants (melting point, lattice constant, yield strength, etc.) must be provided via public-domain descriptions; otherwise, the entry will be reset and refactored.

### 2. Robustness Over Peak Performance
**Robustness > ultimate performance.** All designs must balance cost, durability, and fault tolerance. The baseline is the **human 60-point generic solution**, and the target is locked at the **90-point production-grade solution**, requiring a magnitude leap (e.g., 50% cost reduction or 2× performance improvement).

### 3. Expression & Data Presentation Discipline
**Strip away all subjective positioning, rhetoric, and vague expressions.** Only physical parameters, quantitative thresholds, and failure modes are retained. All domain jargon must be annotated in natural physics language for qualitative comprehension. **Tables are strictly prohibited**; parameter comparisons use plain text flows with arrows "→" to establish clear causality, ensuring Grep-friendliness, distortion resistance, and data retrievability.

## VI. Quality Standards & Parameter Reserve Strategy

### Scoring Anchor
- **60-Point Baseline**: Existing generic academic/industrial solution, already at its performance ceiling.
- **90-Point Target**: Novel multi-dimensional closed-loop architecture achieving magnitude leap (50% cost reduction or 2× performance improvement).

### Reserve Strategy & Parameter Back-Calculation Mechanism
The final 10% of critical parameters (e.g., on-site impedance matching, micro-stress calibration, operating-condition coefficients) **are not fixed**. They are uniformly expressed using the standard engineering phrasing:

> **"This parameter must be determined by back-calculating [Y] from on-site measured data [X]."**

**The acquisition of [X] must comply with the following physical constraints:**
[X] must be a directly measurable physical quantity (temperature, pressure, voltage, dimension, etc.), a public nominal value of a known material grade (yield strength, resistivity, thermal conductivity, etc.), or a value obtainable within 24 hours via standard test methods (ISO/ASTM/GB, etc.).
**Strictly prohibited**: Any [X] requiring "customized fabrication, imported equipment procurement, new test method development, or third-party testing with >72-hour turnaround."

**If [X] cannot be directly measured on-site, the following priority sequence applies:**
1. **Preferred**: Output a measurable surrogate parameter (e.g., surface hardness as a proxy for residual stress).
2. **Secondary**: If no direct substitute is available, provide an estimation model (e.g., back-calculate interface temperature via thermal balance equations).
3. **Baseline**: If the estimation model is not feasible, provide a physical upper bound calculation (worst-case parameters do not exceed a certain value, and the solution remains valid within that bound).
4. **Fallback**: Only after all the above attempts fail, the following determination is issued: *"Human toolchain has not met the requirement — this is not a failure of the proposed solution."*
